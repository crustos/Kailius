# Kailius Mini (Stride2D)

The same level and the same game scripts as the Prowl2D mini, but on [Stride2D](https://github.com/crustos/stride2D):
C# in the subset it translates to C, shipped as **one native executable with no .NET in it**, and now **with a window,
a keyboard and the Kailius art**. Generated by `build.py mini stride2d`. Do not edit this folder in place.

## Build and run

    python3 build.py mini stride2d --build --stride2d /path/to/stride2D

That runs Stride2D's `player` command on `KailiusMini2D/`, runs the native result and requires its output to be
identical to the same game on .NET (`--verify`). Needs, once, in the Stride2D checkout: `python3 build.py deps`,
`native`, `ccsharp`, the .NET 10 SDK (translator only) and a C compiler.

## Playing

The bot plays until you press a key; the first movement key hands the game to you.

| Key | |
|---|---|
| Left / Right, A / D | move |
| Up, W, Space | jump (once more in the air) |
| Escape | quit |

With no display the renderer draws offscreen (`STRIDE2D_GFX=soft` forces the CPU rasteriser), the bot plays, and the
run prints its progress and a hash of the last frame.

## What is shared and what is not

`Layers`, `Shared`, `Player`, `Slime`, `Pickups`, `Bot` and `World` are the Prowl2D mini's files with the namespaces
swapped, so both ports play identically (the same fixed 0.01 s step gives the same positions). Only `Input.cs`
(keyboard), `View.cs` (sprite batch, camera, health bar) and `Game.cs` (window loop) are Stride2D's own.

## The art

`build.py` bakes one texture atlas from the real PNGs (no image library needed: it has its own PNG reader) and writes
it into `Atlas.cs` as run-length data, because the C# subset has no array or string data literals; the game rebuilds
the texture at start-up. In it: the adventurer (idle, 6 walk and 4 jump frames), the coins, the portal, the grass block
of the tile set cut into nine 32 px tiles that `View.cs` tiles over every collider rectangle, and, for a real scene,
the walking animation of each enemy kind in it, the torch (stick and flame) and the trap tiles' own sprite. Sprite
sizes follow the prefabs (the adventurer and slime at scale 2, the coin 0.5, the portal 0.8, 32 pixels per unit).
The sky is a gradient, not the background image. The black bar under the portal is part of the original sprite.

## Enemies, traps, torches and text

Read from the prefabs, scripts and scene (`--scene Scene_1`), not written by hand:

| In Kailius | Here |
|---|---|
| `Patrol` enemies (Slime, Bee, Crab, Ghost, Ghoul, Hellcat, Skeleton, Slug, GhostHalo) | `EnemyScript`, patrol: speed, health, collider and walk animation from the prefab; turns at ledges and walls |
| `Boss` + `BossRun` + `BossWeapon` (Tru, Knight, Piranha, Vampire) | `EnemyScript`, boss: faces the player, runs at them within `BossSense` (15, from `BossRun.cs`), stops in range, swings after a wind-up for the prefab's `attackDamage`, then cools down |
| `Enemy.TakeDamage` | the mini has no sword, so landing on an enemy does 100 (a slime dies, a boss takes five, with half a second of recovery); a bar shows a boss's health |
| `Traps` tilemap (25 damage) | solid tiles drawn with their own sprite; touching them costs 25 and puts you back at the respawn point |
| `Flame1` | a decorative torch (it is a light, not a hazard), flickering through its animation clip |
| HUD | health bar, HP, score, coins and kills drawn with the renderer's DejaVu font; banners for death and for reaching the portal |

Not ported: the ranged wizards (`WizzardNormal`, `WizardBoss`), pickups other than coins and gems (hearts, swords, shields,
chests), enemy drops, hurt and death animations, the parallax background, sound.
